# ADR 0014: Triage by swipe, an applications board, a description excerpt and an installable page

**Status:** accepted (2026-10-21, M23). Amends ADR 0009 (the dashboard allow-list) and ADR 0012
(verdict labels, decisions API).

## Context

The Aujourd'hui table made me scan 150 rows to decide anything. Deciding one offer at a time is
faster, and every decision should feed `calibrate`. A decided offer then needs a place to live
until the application ends, even after the offer closes. The dashboard is mostly opened on a
phone, from the home screen if possible.

## Decision

1. **Tri replaces Aujourd'hui.**
   - The queue is every untriaged (to_review) row. Offers collected since the latest `jobs` run
     come first ("Nouveau"), then the most recently collected, then the best scored. There is no
     "last triage" marker: to_review already means untriaged, and the run date is in data.json.
   - Right = to_apply + verdict good_fit. Left = ignored, plus an optional verdict picked in one
     tap.
   - Batches of 20.
   - The pure rules (queue, batches, swipe records, undo stack, retry queue) live in
     `assets/triage.js` and are tested in Node.
2. **A fifth verdict, `location`.** D1 migration 0003 rebuilds `decisions`: SQLite cannot alter a
   CHECK in place. The Python mirror has no CHECK and is unchanged.
3. **Undo deletes the verdict:** `DELETE /api/decisions/:id`, with the same Access and origin
   checks. Without it, an undone swipe would still count in `calibrate`.
4. **Failed saves wait.** A network error or a 5xx goes to an in-page retry queue (flushed on
   `online`, every 15 s, or by hand); a 4xx reverts.
   - The queue is not persisted: closing the tab with actions pending loses them, and the banner
     says they are pending.
5. **Candidatures** is a board of to_apply / applied / interview / rejected, with due follow-ups
   on top. "J'ai postulé" sets applied_at and offers follow_up_at = +7 days.
   - `data.json` gains `tracked`: the jobs behind an application, closed or past the age cut-off
     included.
6. **`description_excerpt` joins the allow-list:** plain text (tags and entities removed),
   whitespace collapsed, at most 600 characters. It is set with `textContent`, and a test fails
   if any dashboard script uses an HTML sink.
7. **Installable, never cached.**
   - Shipped: a web app manifest (`crossorigin="use-credentials"`, so Cloudflare Access sends its
     cookie), PNG icons generated by `scripts/build_icons.py`, and `manifest-src 'self'`.
   - No service worker: current Chrome, Edge and iOS install without one, and nothing may serve
     a stale data.json.

## Alternatives

- **A swipe library:** Pointer Events cover mouse, touch and pen in about a hundred lines, with
  no dependency to vet.
- **A "last triage" timestamp, in D1 or localStorage:** redundant with to_review, and
  localStorage differs between devices.
- **HTML5 drag and drop for the board:** unreliable on touch. Pointer Events on desktop plus a
  status menu everywhere.
- **A caching service worker:** fast reopen but stale statuses; rejected.

## Consequences

- Verdicts arrive at the swipe rate, so `calibrate` gets usable numbers within days.
- Each listed job carries up to 600 characters of its description in the page. The page sits
  behind Access, and `site/` is never published or uploaded.
