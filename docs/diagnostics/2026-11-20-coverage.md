## 4. Workday

### 4.1 Ce qu'est le 429

Mesures du 20 novembre, depuis une machine qui n'est pas un runner GitHub :

| Client | Rythme | Résultat |
|---|---|---|
| curl (User-Agent par défaut ; un appel avec celui de httpx) | 3 s | **26 / 26 en 200** |
| httpx (bibliothèque Python du projet), User-Agent par défaut | 2,5 s | 0 / 11 |
| httpx, User-Agent neutre | **5 s** | 1 / 6 |
| httpx, User-Agent « curl » | 3 s | 1 / 2 |

Le corps du 429 est une page HTML « Security Check — Enable JavaScript and cookies to
continue » avec un identifiant de support, servie par Cloudflare, **sans en-tête
`Retry-After`**. En production (même bibliothèque, User-Agent du projet) une partie des appels
passe : 47 fiches Thales sur 100, chacune après jusqu'à 4 essais. L'attente n'y change rien :
le tout premier appel Workday du run reçoit déjà un 429.

Conclusion : depuis le 16 novembre, l'edge de Workday classe le client Python comme
automatisé et lui présente un défi, **quel que soit le débit**. `robots.txt` (lu sur un
tenant) n'interdit pas `/wday/cxs/` : il interdit les pages HTML du site.

**Ce que la PR fait** (demandé) : file d'attente unique pour tous les tenants, délai
configurable (1,5 s), respect de `Retry-After`, backoff plus long (5 s puis 10 s au lieu de
1, 2, 4), abandon d'un tenant après deux appels ratés de suite sans arrêter les autres,
journal qui nomme la page de sécurité.

Sur le nombre de réessais, j'ai fait l'inverse de ce qu'on fait contre un quota : **moins
d'essais** (3 au lieu de 4). Le run du 20 novembre a obtenu ses 112 offres en insistant 568
fois contre le défi ; attendre plus longtemps n'aurait rien débloqué et aurait allongé le run.
Tout est réglable dans `config/settings.yaml` (`sources.ats.workday`).

**Ce qu'elle ne fait pas** : passer le défi. Changer l'empreinte réseau du client pour
ressembler à curl ou à un navigateur (HTTP/2, empreinte TLS, User-Agent) serait contourner un
anti-bot : c'est interdit par tes règles, je ne l'ai ni fait ni essayé. **Il est donc probable
que le prochain Daily run récupère peu d'offres Workday, voire moins que les 112 du
20 novembre** tant que le défi est servi. Ce qui change : un tenant qui refuse coûte de
l'ordre d'une minute au lieu de bloquer le run 25 minutes, le projet n'insiste plus, et le
journal dit pourquoi. Le jour où Workday répond, les onze boards se lisent en 19 minutes
environ.
